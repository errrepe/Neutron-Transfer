## 1. Contexto técnico para os subagentes

### 1.1 O crash B1 (crash log simbolizado)

```
EXC_BREAKPOINT / SIGTRAP — main thread
libswiftCore  _assertionFailure
SwiftUICore   EnvironmentValues.subscript.getter        ← leitura de @Environment(Tipo.self) sem objeto injetado
SwiftUICore   EnvironmentBox.update(property:phase:)
SwiftUICore   DynamicBody.updateValue()
SwiftUICore   DynamicViewList.updateValue()
SwiftUICore   ForEachState.forEachItem / ForEachList.applyNodes   ← montagem de uma lista dinâmica de views (pilha de navegação ou itens de toolbar)
(nenhum frame do app além de main)
```

Gatilho observado: selecionar a pasta `QA-2026-10-02-a` (recém-criada, vazia) e
pressionar Return → `Table.primaryAction` → `BrowserModel.openSelection` →
`path.append(...)` → a `NavigationStack` monta o destino → crash.

Código envolvido:
- `Features/Browser/BrowserContainerView.swift`: `.environment(model)` e
  `.environment(model.session)` aplicados **fora** da `NavigationStack`, depois de `.searchable`.
- `Features/Browser/FolderView.swift:17` e `FolderTable.swift:16`: leem `@Environment(BrowserModel.self)`.
- `Features/Transfers/TransfersToolbarButton.swift:13`: lê `@Environment(AppSession.self)`
  **dentro de um `ToolbarItem` de cada `FolderView`**, inclusive dos empilhados.
- `FolderView` também tem `.toolbarTitleMenu { ForEach(...) }`, `.sheet`,
  `.confirmationDialog` e `.alert`.

Os itens de toolbar e o conteúdo de `navigationDestination` são hospedados pelo
SwiftUI fora da hierarquia "normal" da view. O objeto injetado por fora da stack
pode não chegar até eles. **A correção (R2) elimina a classe inteira do problema**:
as views do browser passam a receber o model **por parâmetro**, sem depender do
environment.

### 1.2 Pastas duplicadas (D1)

`Core/Transfers/DriveUploadAdapter.swift`, em `ensureFolder` (≈ linhas 70–95):
```swift
for candidate in [name, "\(name) (1)", "\(name) (2)"] {
    do { … createFolder(candidate) … }
    catch let e as ProtonAPIError {
        switch e { case .api: lastError = e   // "maybe a duplicate — try the next suffix"
                   default: throw e }
    }
}
```
Qualquer erro `.api` vira um novo nome. Para upload de árvore, o comportamento
esperado (igual ao Proton web e ao Finder ao copiar para dentro de uma pasta que
já existe) é **mesclar**: reusar a pasta que já existe e enviar os arquivos para
dentro dela. `FolderOperations.swift:83–90` já documenta o código de duplicado:
**2500** (`AlreadyExists` → `NodeWithSameNameExists`, ProtonDriveApps/sdk).

### 1.3 M1 não é bug

O app está em inglês (sem localização pt-BR ainda) e o Mac do usuário está com
região Brasil. O macOS formata números e datas pela **região** e textos pelo
**idioma**. Por isso "2,15 GB" no meio de texto em inglês é o comportamento correto e
igual ao Finder. **Não mudar.** A mistura some se a S4.4 (pt-BR) do plano-mãe for
feita. Registre no relatório final do R7 como "won't fix — comportamento do sistema".

### 1.4 Limitações do cua-driver (para os agentes de QA)

- `hotkey` com atalho de menu (⇧⌘N, ⌘U, ⌘V…) **não funciona em background**.
  Use `invoke_menu` com o caminho do menu (ex.: `["Edit","Paste"]`, `["File","New Folder"]`).
- `NSOpenPanel` e arrastar do Finder não são automatizáveis em background: ficam
  para o checklist humano.
- Duplo-clique sintético em linha de `Table` pode não acionar `primaryAction`.
  Para abrir pasta, prefira selecionar a linha e usar `invoke_menu ["Go","Open"]`
  (⌘↓) ou `press_key return`.
- Antes de qualquer QA, confirme que **só existe uma instância** do app
  (`list_windows` filtrando por app). O QA de 2026-10-02 achou uma instância órfã
  antiga do Xcode rodando junto.
